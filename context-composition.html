Context Composition

一次模型调用的 context，最基本可以看成两部分：messages[] 和 tools[]。前者是对话内容，后者是工具 schema；它们并排传给 provider。

messages[]

模型真正读到的对话序列，按顺序拼好。

S

System message

基础身份、运行环境、项目规则、用户/工作区信息、记忆、当前激活的 skill 等。下面有详细展开。

identity runtime AGENTS.md memory active skill
H

History messages

之前已经保存的 user / assistant / tool 消息。这里会保留合法的工具调用配对。

prior user prior assistant prior tool calls prior tool results
U

Current user message

本轮用户输入，加上当前时间、会话、工作区、模式偏好等运行时上下文。

current request time workspace mode/source
A

Assistant tool-call message

如果模型要调用工具，会先追加一条 assistant 消息，里面带 tool_calls。

T

Tool result messages

每个工具结果都会作为 role: tool 消息追加，并通过 tool_call_id 对回去。

F

Final assistant message

当模型不再请求工具时，最后的 assistant 内容就是本轮回复。

tools[]

工具定义单独传入，不是粘进 system prompt。

  • Filesystem tools read_file、write_file、edit_file、list_dir。
  • Shell / execution tools 例如 exec，用于运行项目命令和脚本。
  • Search / web / MCP tools 按当前运行环境注册成 function schemas。
  • Message / spawn / cron 用于发最终内容、派生子任务、安排提醒等。
关键点：messages[] 是模型读的上下文文本；tools[] 是模型可调用工具的结构化定义。每次模型调用都会把这两部分一起提交。

System Message Composition

ContextBuilder.build_system_prompt() 会把下面这些片段按顺序拼成一条 role: system 消息，中间用 --- 分隔。

1. Identity / runtime

来自 nanobot/nanobot/templates/agent/identity.md。包含运行系统、workspace 路径、memory / history / skills 路径、平台策略、搜索发现规则、文件发送规则。

2. Project workspace notes

由 _get_identity() 追加。再次说明长期上下文目录，以及 skills/{skill-name}/SKILL.md 是只读指令，不应该把运行输出写进去。

3. Bootstrap files

依次读取 workspace 根目录的 AGENTS.md、SOUL.md、USER.md、TOOLS.md。存在才加入；当前项目实际加入了 AGENTS.md。

4. Memory

来自 MemoryStore.get_memory_context()。如果 memory/MEMORY.md 不是默认模板且有内容，就作为 # Memory 加进 system message。

5. Active Skills

如果本轮指定了 skill，例如 simple，会读取对应 skills/simple/SKILL.md 的正文，放到 # Active Skills 下面。

6. Skills summary

来自 agent/skills_section.md 模板。它列出可用 skill 的名称、描述和位置，提醒模型如需使用某个 skill，应读取它的 SKILL.md。

7. Recent History

如果 Dream 之后还有未处理历史，会最多取最近 50 条，限制到约 32k 字符，追加为 # Recent History。

Provider shape

最终进入 messages[0]：{ role: "system", content: "..." }。工具 schema 仍然在 tools[]，不会塞进这段文本。

One Turn Flow

一轮用户请求里，如果需要工具，模型可能会被调用多次。

  1. 1. Build context 拼出 system、历史、本轮 user message。
  2. 2. Send to model 同时提交 messages[] 和 tools[]。
  3. 3. Append tool results 如果有工具调用，把 assistant tool_calls 和 tool 结果追加进消息列表。
  4. 4. Final answer 没有新的工具调用后，保存并返回最终 assistant 回复。
